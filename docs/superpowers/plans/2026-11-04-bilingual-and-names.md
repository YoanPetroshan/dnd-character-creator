# Plan: bilingual BG/EN app (engine messages, UI copy, exports) and a random-name dice button

Opus planner, 2026-11-04 (read-only; counts by AST/grep at HEAD da3fb95). Condensed; the full report is the source of the slice specs below.

## Requirements and decisions (user, 2026-11-04)

(1) A language switch BG/EN somewhere in the app (persisted per device). In BG mode everything is Bulgarian EXCEPT the game terms/names that stay English as today (class/species/feat/spell/item names, feature names, rule texts). In EN mode use the dictionary and wording of the SOURCES as literally as possible (glossary with citations), including engine messages and the exports. (2) A dice button next to the character Name field fills a random name: random first name + gender-matching surname from large built-in sets (>= 30 each, aim 60-80; authentic/historical Bulgarian, not foreign borrowings); in EN mode the same names transliterated to Latin. (3) Offline: the same code path must work in-process (Pyodide worker), so language is an explicit argument, never HTTP negotiation. (4) Link sharing is cancelled.

Planner decisions E1-E4, resolved by the parent with defaults the user can flip: **E1** names with Greek/Hebrew/Latin roots (Иван, Георги, Христо, Васил, Симеон, Самуил, Калоян, Кераца, Гергана, Тонка, surnames Иванов, Петров...) are tagged `christian` and EXCLUDED by default because the user asked for authentic/historical Bulgarian and NOT borrowed names (the lists still meet the minimum: 31 male, 31 female first names, 54 surnames); one constant switches them on; the user is asked whether to include them. **E2** word-final "ия" follows the official Bulgarian streamlined transliteration law ("-ia"). **E3** when 2014 and 2024 terms differ, the EN UI uses the 2024 PHB term everywhere. **E4** engine-written rule paraphrases (reference_data notes, feat-effect notes, class resource notes) are rule text and stay English in BG.

## Key facts and design (Option 2b: tagged messages)

- Engine output is English and pinned by the golden (237 of 251 cases contain at least one message/pruned/disabledReason, about 3,281 leaves) and by ~252 assertions in 57 test files; the engine also COMPARES its own English strings in logic (`resolve.py` ~1530/1551 `tpl["label"] == "Skill Proficiencies"`, ~2966 `startswith("already taken")`, ~5492 `"final" not in message`), so replacing English by translation inside the engine would break behavior.
- Recommendation: `server/i18n/messages.py`: `class Msg(str)` (subclass carrying `.key` and `.params`; JSON-serializes identically, still passes `==`/`startswith`, survives deepcopy via `__reduce__`); `msg(key, **params)` renders the EN template so today's text stays byte-identical; `render(m, lang)`; `localize(resolution, lang)` deep-walks and replaces Msg values (lang `en` returns the input untouched). Catalog `server/i18n/catalog/{problems,warnings,pruned,disabled,labels}.py` merged into `MESSAGES[key] = {en, bg}` with `str.format` templates and a plural filter `{n|one|many}`. `resolve(draft, catalog)` keeps its signature; callers do `localize(resolve(...), lang)`: `app.py` `/api/resolve?lang=bg|en` (missing = en, other = 400 `{error}`), the `/api/export` 400 `{problems}` body, later the Pyodide worker with the same Python code.
- Counts: about 215-240 emission sites, ~170-200 catalog keys, ~70% templated; problems/warnings already have ~68 stable id families; pruned has only `choiceId`+`reason`; `disabledReason` has no id. `app.py` `{error}` strings are transport errors and stay English (the client maps HTTP status via `httpErrors.ts`).
- Safety net the golden does not give: a frozen EN message snapshot `server/tests/golden/messages_en_snapshot.json.gz` taken from HEAD BEFORE any conversion using a "message zoo" (`server/tests/i18n_zoo.py`: every golden draft; the same with selections cleared; levels halved; ruleset switched to 2024; the 2024 kitchen sinks; hand-written triggers for every problem/warning id family); every slice must keep it identical; it only grows via `--append`, never `--regenerate`. Golden policy for the whole series: golden untouched, no REBASELINES entry; any golden/snapshot diff is an executor error: stop and report.
- Exports: 147 Cyrillic literals in markdown_export/pdf_export/export_fields; YAML has none (no EN version needed); new `server/export_labels.py` (`LABELS = {"bg": {...}, "en": {...}}`), `to_markdown(resolution, lang="bg")`, `to_pdf(resolution, lang="bg")` (default bg keeps all current output byte-identical), `/api/export/<fmt>?lang=`; PDF font DejaVu covers both scripts; unnamed fallback per language; filename fallback per language.
- UI: 301 non-test lines with Cyrillic across 30 files. `frontend/src/copy/{bg,en,index}.ts` (`bg.ts` source shape `as const`, `en.ts` typed `Copy` so missing keys fail `tsc`), `LanguageContext.tsx` (`localStorage["dnd-builder-lang-v1"]` = bg|en, default bg, `document.documentElement.lang`), above LibraryProvider; the language is not stored in drafts; `useResolution` sends `?lang=` and re-resolves on switch; pure logic modules (mergeDraft/library errors/exportReadiness/httpErrors) return `{code, params}` rendered with `t`.
- Glossary: `server/i18n/glossary.json` `{termId: {en, bg, cite:{src, locator}}}`; generated `docs/GLOSSARY.md` and `frontend/src/copy/glossary.gen.ts` with a drift `--check` test; sources by precedence: 2024 PHB markdown (/Users/yoanpetrov/Downloads/Player's Handbook (2024).md: Ch.1 abilities/saves/proficiency/initiative/hit points/conditions, Ch.2 step 5, Multiclassing, Ch.4, Ch.6, Ch.7, Rules Glossary), SRD JSON, 5etools data labels; cites verified only when the file exists (PHB lives outside the repo: skipped in CI; SRD/5etools always verified). Starter terms: Armor Class, Hit Points, Hit Point Dice, Proficiency Bonus, Saving Throws, Skills, Initiative, Speed, Passive Perception/Insight/Investigation, Ability Scores, Spell Save DC, Spell Attack Bonus, Spell Slots, Cantrips, Prepared Spells, Spellbook, Species, Background, Origin Feat, Feats, Class Features, Languages, Equipment, Weapon Mastery, Size, Senses, Darkvision, Resistance, Immunity, Vulnerability, Short/Long Rest, Carrying Capacity, "ft.", "GP".
