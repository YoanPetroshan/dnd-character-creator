### i18n overview

- **Layers.** (1) `server/i18n/glossary.json`: rules terms `{en, bg, cite}` -> generated `docs/GLOSSARY.md` and `frontend/src/copy/glossary.gen.ts`. (2) Engine messages: `server/i18n/messages.py` (`Msg` = a `str` carrying `key` and `params`; `msg(key, **params)`, `render`, `localize`, plural filter `{n|one|many}`, list join `{names:, }`, `parse_lang`) and `server/i18n/catalog/{problems,warnings,pruned,disabled,labels}.py` (`MESSAGES[key] = {"en", "bg"}`); the engine writes English-text `Msg`s, `app.py` runs `localize(resolution, lang)` on the finished resolution. (3) Exports: `server/export_labels.py` (`LABELS = {"bg", "en"}`, `label`, `word`), used by `markdown_export.py`, `pdf_export.py`, `export_fields.py`. (4) Web UI: `frontend/src/copy/{bg,en,index}.ts` (`Copy = typeof bg`, `copyFor(lang)`), `LanguageContext.tsx` (`useLang`, `useT`, `<html lang>`, `dnd-builder-lang-v1`), `LanguageSwitch.tsx`, `logic/messages.ts` (`Msg`, `renderMsg`), `logic/langQuery.ts` (`withLang`). (5) Names: `names/bgNames.ts`, `logic/translit.ts`, `logic/randomName.ts`. (6) Review: `server/i18n/review_table.py` -> `docs/I18N-REVIEW.md`.
- **Request path.** The frontend appends `?lang=` to `/api/resolve` and `/api/export/<fmt>`; `app._request_lang()` -> `parse_lang` (missing = `en`, bad = 400); `localize` swaps every `Msg` for its rendering; Markdown / PDF take `lang` too (missing = `bg` there). Catalog / items / spells requests carry no language (their text is data).
- **Add a server message.** Add `"<key>": {"en": ..., "bg": ...}` (same `{params}`) to the module of its kind; emit `msg("<key>", name=...)` at the site, never an f-string, `+`, `.strip()` or `join` on a `Msg` (the tag is lost and the text stays English); a count uses `{n|one|many}`, a list `{names:, }`, a nested piece is a `Msg` param. The AST guards of `test_i18n_problems/_pruned/_disabled/_labels.py` fail on a plain-string site or an unused / missing key. English text must stay byte-identical (`test_i18n_snapshot.py`): extend the snapshot only with `tests/i18n_zoo.py --append`.
- **Add a glossary term.** Add it to `glossary.json` (`en` from the 2024 PHB, then the SRD; `bg`; a `cite` locator), run `cd server && ../.venv/bin/python -m i18n.glossary`, commit the two generated files; use it in `en.ts` as `g.<term>.en`, in `bg.ts` as a literal equal to `bg` (pin it in the MAP of `copyGuards.test.ts` and in `export_labels.GLOSSARY_LINKS`).
- **Add an export label.** The same key (and placeholders) in `_BG` and `_EN` of `export_labels.py`; Bulgarian text changes need `WRITE_EXPORT_BASELINE=1` on purpose (the BG output is pinned by `export_baseline.json`).
- **Add a copy key.** Add it to `bg.ts` (structured by area), the same path to `en.ts` (`const en: Copy`: a missing key is a tsc error); templates are functions with the same parameters; no Cyrillic outside `copy/` (copyGuards AST scan; `names/bgNames.ts` and `logic/translit.ts` are the only content files). A new BG text that is an English word needs the LEGACY allowlist entry in `copyGuards.test.ts`.
- **Add a flagged wording.** A line in `FLAGS` of `review_table.py`, regenerate `docs/I18N-REVIEW.md` (`--check` runs in the suite).
- **Test map.** Server: `test_i18n_messages.py` (core: `Msg`, render, localize, plural, `parse_lang`, HTTP), `test_i18n_snapshot.py` (frozen English message snapshot, 1163 cases), `test_i18n_problems.py` (118), `test_i18n_pruned.py` (56), `test_i18n_disabled.py` (74), `test_i18n_labels.py` (133), `test_glossary.py`, `test_export_labels.py` + `test_export_baseline.py` + `test_export_completeness.py` (exports, BG byte identity, EN no Cyrillic), `test_i18n_completeness.py` (C1, cross-layer), `test_i18n_review.py`. Frontend: `copyGuards.test.ts` (parity, placeholders, no Cyrillic in `en`, LEGACY allowlist, glossary pins, AST scan), `bgRender.test.ts` (BG render snapshot of 8 routes x 10 states, English render has no Cyrillic), `LanguageContext.test.ts`, `LanguageSwitch.test.ts`, `logic/messages.test.ts`, `names/bgNames.test.ts`, `logic/translit.test.ts`, `logic/randomName.test.ts`, `randomNameButton.test.ts`. Manual: REAL-DEVICE-CHECKLIST rows 15-19.
- **Known English leftovers (on purpose).** (1) Text the DATA supplies in both languages: class / species / feat / spell / item / skill / language / damage-type names, class feature and trait names, 5etools descriptions, an equipment envelope's "(a) ... or (b) ..." text, option labels, feat groups, "Nx Item", "(N SP)" marks. (2) Rules terms with no translation: Expertise, Fighting Style, Maneuvers, Metamagic, Eldritch Invocation (the tail of a `label-prefixed` card label), and class names inside Bulgarian messages ("на warlock", "Bard"). (3) The engine's rule paraphrases (notes, resource text). (4) `instance_label` ("Agonizing Blast (2)"). (5) The `{"error": ...}` transport texts of the API. (6) The Bulgarian export keeps the English `Spell Slots`, `Pact Magic Slots`, `versatile`, `off hand`, `range`. (7) The Bulgarian web UI keeps the English words of its LEGACY list (page names, `Character Name`, ability-method labels, the Export attack and carrying lines). (8) YAML has no localized labels. (9) The character's own text (name, details) is printed as typed. (10) Two preserved quirks: the Export attack line prints the literal `null` for an attack with damage but no damage type; senses always say `фута`.
